# M3 第四轮：评价、超时升级与基础统计实施计划

基线 `f968b8f9a08daae73ca6ddd194d47d40f0dee07d`，分支 `feat/m3-reporting`。依据总约定 v0.2、需求 v0.4、M3-01.6/01.7、M3-02.1/02.2。沿用已有领域设计与用户授权，在本会话逐项本地实现；不创建工作树、不自动提交/上传/合并。7 天评价窗口、4/24 小时时限和权限映射仍为待评审提案，不替团队决定。

## 方案和契约

1. 复用 EVALUATE 领域动作：本人 COMPLETED、完成后不足 7 天、整数 1～5、文字不超过 500 字、只能一次；同键重试返回原结果，异键重复拒绝，不触发资源操作。Action 新增 score；其他动作携带 score 拒绝。详情提供评价、评价截止、阶段与累计耗时。
2. 复用 Escalate：到期 `now >= deadline`，按工单/阶段/等级唯一持久化；升级不改变业务状态、不解除阻塞。事务内保存快照、升级记录、审计和通知意图。同步结果未知的工单先核对资源，不按旧阶段升级；重派沿用原期限和升级标记，重启补扫。
3. 主管名单从公开身份目录按当前权限/区域读取；升级仅向有效辖区主管写待投递意图。缺主管或目录不可用时保存可见异常，随后按原升级记录重试路由，不重新升级。已离开原阶段的通知意图不再补建。仍不宣称外部通知已送达。
4. 新增 `/api/v1/m3/escalations` 和 `/stats`，仅 M3 授权区域可读。主管与显式升级异常读取权限可看脱敏升级记录；异常读取权限不自动获得工单详情/派单权限。统计只返回聚合，无学生身份、联系方式或评价全文。

## 数据与允许范围

新增候选 `009_m3_escalations.sql`，仅创建 M3 升级记录表，含事件 ID、工单、阶段、等级、政策版本、阶段状态/期限、检测时间、路由状态与重试时间；唯一 `(workorder_id,stage_number,level)`。不改 001～008。评价仍保存既有工单快照，命令/事件/outbox 同事务；不另造资源/用户表。仅修改 M3、M3 装配/页面/契约和需求证据，不改 M1/M2/D 内部实现或角色种子。

新增 M3 内部权限提案：`workorder.stats`、`workorder.escalation.read`；沿用 `workorder.supervise`。仅显式本机开发绑定可临时映射，正式公共授权待对接。主管不能因此获得派单、验收或解除维修阻塞权限。

## 指标定义

统计按上报时间 `[from,to)`、类别与当前授权区域选取工单。取消工单单列，排除耗时/评分/超时率分母。派单=首派-上报，首修=首次开始-上报，有对应时间才入样本；累计维修和验收仅统计 COMPLETED 工单的已关闭阶段，避免把未完成片段混入均值。评分只含已评价完成工单，无评分时均值为 null，不以 0 分参与。超时率为“已有持久化升级记录的工单数 / 非取消工单数”，标为已记录超时率，资源未确认数单列；不伪称全面实时超时率。
