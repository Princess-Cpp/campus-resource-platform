# M3 第四轮：评价、阶段超时升级与基础统计

日期：2026-10-22；分支 `feat/m3-reporting`，实施基线 `f968b8f9a08daae73ca6ddd194d47d40f0dee07d`。依据总约定 v0.2、需求基线 v0.4、范围分级和[本轮计划](../superpowers/plans/2026-10-22-m3-evaluation-operations.md)。沿用用户授权的既有设计推进。实施结束时保留本地变更，用户随后授权“检查无误可上传”；本次按[上传前复核](../local-review/2026-10-22-m3-round4-prepublish.md)仅交付到团队仓库开发分支，不合并或部署。自动测试和虚构账号演示不代表用户正式人工验收或组内评审。

## 已实现

前三轮的报修、派单、维修和验收恢复继续保留，本轮补齐：

- 本人已完成工单的一次性评价。评分整数 1～5、选填文字最多 500 字，按工单保存的评价窗口截止；当前提案为完成后不足 7 天。评价保持 COMPLETED，不触发资源请求。同键重放返回原结果，即使随后过期也不重复评价；换键再评、改评分、评价他人工单、未完成和到期边界均拒绝。
- 阶段超时升级。按已有提案，未派单/未开始分别 4 小时、累计维修/待验收分别 24 小时。到期即 `now >= deadline`，每工单/阶段实例/等级只生成一次事实。升级只增加标记与版本，不改变业务状态、不释放维修来源。重派不刷新阶段或期限；验收返工形成新阶段、继续累计维修耗时。
- 主管待办与升级异常查询。通知只选择当前启用且有辖区主管权限的人员；缺主管或目录不可用时持久化异常。每 30 秒按原升级记录重试路由，恢复后不再次升级；原阶段已经结束时停止补建通知。
- 当前授权区域的聚合统计：工单状态、首派/首修响应、已完成工单累计维修/验收处理耗时、已记录超时率、评分数量和均分。没有输出学生身份、联系方式或评价全文。

7 天、4/24 小时、主管角色及新增权限映射仍为待评审提案，没有更改 DEC 状态。系统管理员不会自动变成物业主管；主管不会自动取得派单、验收或解除维修限制权限。

## 数据、接口与适配

新增候选迁移 `009_m3_escalations.sql`，不改已执行的 001～008。升级表保存事件 ID、工单、阶段、等级、政策版本、原阶段状态/期限、检测时间、路由状态、下次路由时间和更新时间，唯一键 `(workorder_id,stage_number,level)`。

升级在同一事务中保存工单快照、阶段升级记录和审计。通知路由使用该事件 ID，在另一事务中检查当前阶段并保存主管 outbox/路由结果；投递失败不会再次调用业务升级。审计失败整笔升级回滚；outbox 写入失败保留原升级记录和未路由状态。目录查询不跨网络持业务锁，继续调用公开身份目录，不读取或改写 D 内部表。

路由状态：PENDING、NO_SUPERVISOR、DIRECTORY_UNAVAILABLE、QUEUED、OBSOLETE。QUEUED 仅表示主管通知意图已保存，尚未送达。普通报修人和维修人不会因超时事件自动收到主管升级通知；原有普通动作通知规则保留。

既有后台循环改为 `Sweep`：先核对资源操作，再扫描业务阶段，最后重试升级路由。资源核对最多占用其中 20 秒，给其他工单的阶段扫描保留执行机会；资源同步未知的工单不根据旧阶段升级。没有资源客户端配置时仍可扫描文本报修的派单超时。该进程内 ticker 仍是开发装配，不声称已接入 M2 的正式共享任务库。

评价沿用既有工单快照、命令、审计和 outbox 事务，不新增评价表。详情新增评分、评价截止、阶段编号、升级标记、政策版本及已完成维修/验收段累计秒数。历史领域快照字段保持兼容。

M3 OpenAPI 仍 pending-team-review，增量变化：

|接口|规则|
|---|---|
|POST `/api/v1/m3/workorders/{id}/actions`|新增 EVALUATE 与 score，其他动作不接受评分值；沿用会话、CSRF、版本及幂等键|
|GET `/api/v1/m3/escalations`|当前 workorder.supervise 或显式 workorder.escalation.read，且当前区域匹配；支持页码、类别、检测时间范围、active；返回脱敏元数据和 canOpen|
|GET `/api/v1/m3/stats`|当前 workorder.stats 和区域；按上报时间范围/类别选取工单，返回聚合|

升级异常读取权限不授予工单详情权限：`canOpen=false` 时不显示详情按钮，直接猜工单 URL 仍返回 404。区域比较使用 utf8mb4_bin，与既有服务端规则一致。查询拒绝客户端自行传入 area、scope 等扩权字段。

本机私有绑定扩展 workorder.supervise、workorder.stats、workorder.escalation.read，仍只用于已通过公开注册创建、当前保留基础角色的虚构用户，不写公共角色种子。正式权限定义和公共目录适配仍需 M2/团队共同确认。

## 统计口径

统计按当前权限区域和上报时间 `[from,to)` 选工单，类别可筛选；取消工单单列，不计入下面的分母：

|指标|样本与定义|
|---|---|
|派单耗时|有首次派单时间的非取消工单；首次派单-上报|
|首次维修响应|有首次开始时间的非取消工单；首次开始-上报|
|累计维修均值|仅 COMPLETED；所有维修段累计，返工继续相加，待验收不计入维修段|
|累计验收处理均值|仅 COMPLETED；各待验收段相加；通过申请后等待资源同步的时间不计入，沿用既有领域规则|
|评分均值|已评价的完成工单；未评价不按 0 分参与，空集返回 null|
|已记录超时率|有持久化升级历史的工单数 / 非取消工单数；不是所有尚未确认阶段的全面实时超时率|
|资源待确认|非取消且同步状态非 IDLE 的工单数，单独显示|

页面显示各耗时样本数、评分数量和超时分母。没有样本和实际为零分别显示，避免虚构精确指标或用未完成片段稀释维修均值。
