# M1 首版代码说明

状态：开发实现初稿，未完成跨组联调和生产认证。代码位于 `backend/internal/booking`，前端位于 `frontend`。

## 已实现

- 可用座位查询：日期/时间、区域、插座标记和院系范围过滤；提交时重新检查资源。
- 整点预约：默认最长 4 小时，MySQL 事务和教室锁防止同一教室竞态；M1 来源、幂等键、操作审计和 outbox 事件。
- 本人历史、取消、每日教室签到码和 Web 签到；签到窗口、身份和状态检查在服务端执行。
- 定时任务：提前提醒、迟到提醒、15 分钟未签到取消/违约、结束释放；逻辑通知事件去重，失败可重试。
- M2/M3 资源 HTTP 接口：整室占用、维修阻塞、按来源释放、结果查询和服务身份边界。
- React + Vite 的最小搜索、预约和历史页面；生产静态产物由 Go 应用提供。
- 搜索提交前提示“已过当前时段”和“不允许预约跨天”；结果为空且超出测试教室 08:00–22:00 时提示开放时间。该开放时间取自开发 fixture，接入 D-02 主数据后改为读取各教室规则。
- 我的预约“删除”：`DELETE /api/v1/m1/bookings/{id}`（迁移 003 新增 `hidden_at`）。仅本人已完成或已取消的记录可以从列表移除，同一请求重复执行结果幂等；数据库行和 HIDE 审计保留。待签到、使用中和未签到违约记录拒绝删除（409 INVALID_STATE），他人记录返回 404。接口与 schema 变更待组内评审。

## 当前适配边界

本地开发使用 `M1_DEV_MODE=true` 的显式 fixture 适配器。用户身份已改由 SQL 会话提供，空间主数据和 M2/M3 服务身份仍来自 fixture；它不是正式 D-02 或生产身份实现。后续应替换 `internal/dev` 中的目录和服务凭证，保留公开 `Authenticate`/`Catalog` 接口和行为测试。邮件投递通过开发 SMTP 地址注入；没有配置时事件仍持久化，不宣称外部通知已发送。

资源接口实现是真实 Gin HTTP 路由，但在单应用内监听同一地址；M2 调用端已实现并经真实 HTTP 测试，M3 调用端仍需实现。当前没有直接改其他模块数据库的代码。
