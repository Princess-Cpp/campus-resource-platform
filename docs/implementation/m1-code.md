# M1 首版代码说明

状态：开发实现初稿，未完成跨组联调和生产认证。代码位于 `backend/internal/m1`，前端位于 `frontend`。

## 已实现

- 可用座位查询：日期/时间、区域、插座标记和院系范围过滤；提交时重新检查资源。
- 整点预约：默认最长 4 小时，MySQL 事务和教室锁防止同一教室竞态；M1 来源、幂等键、操作审计和 outbox 事件。
- 本人历史、取消、每日教室签到码和 Web 签到；签到窗口、身份和状态检查在服务端执行。
- 定时任务：提前提醒、迟到提醒、15 分钟未签到取消/违约、结束释放；逻辑通知事件去重，失败可重试。
- M2/M3 资源 HTTP 接口：整室占用、维修阻塞、按来源释放、结果查询和服务身份边界。
- React + Vite 的最小搜索、预约和历史页面；生产静态产物由 Go 应用提供。

## 当前适配边界

本地开发使用 `M1_DEV_MODE=true` 的显式 fixture 适配器，仅用于 M1 独立开发；它不是 M2 的生产身份/RBAC或主数据实现。M2 接入后应替换 `internal/dev`，保留公开 `Authenticate`/`Catalog` 接口和行为测试。邮件投递通过开发 SMTP 地址注入；没有配置时事件仍持久化，不宣称外部通知已发送。

资源接口实现是真实 Gin HTTP 路由，但在单应用内监听同一地址；M2/M3 调用端仍需由对应组实现 HTTP 客户端和端到端证据。当前没有直接改其他模块数据库的代码。

## 验证

此前记录的 `go test ./...` 和本地 smoke 验证属于 M1 初始开发验证；前端构建、MySQL 迁移、并发预约、真实 HTTP 写回和重启恢复仍需在当前环境重新运行并保存证据。本地运行命令见 [第一次项目讨论](../process/first-discussion.md)；不要把开发 fixture 运行结果描述为生产就绪。
