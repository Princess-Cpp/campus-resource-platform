# 项目计划

## 1. 目标与交付范围

校园资源服务平台包含 M1 座位预约、M2 整室申请审批、M3 物业报修及 D 公共能力。课程来源为 [原始任务书](source/Pj-任务书.pdf)；[需求基线](requirements/README.md)定义行为与验收，[范围分级](requirements/scope.md)区分首版必须完成和后续加固。

核心链路：M2 审批通过后对应时段不可个人预约；M3 维修时全室下架，验收后仅解除本工单来源；每项占用可追溯到 M1/M2/M3。权限、并发冲突、来源隔离、基本幂等和重启恢复属于首版必验，不因缩减规模取消。

## 2. 技术与职责

React + Vite、Go + Gin、MySQL，同仓库单应用部署。Go 提供前端产物和业务 API；MySQL 独立运行。通知、审计和任务采用进程内公共库，与业务同事务写事件；只有 M2/M3 → 资源公开接口保留必要真实 HTTP 链路。工具版本和实现方案在骨架任务中固定。

[总约定](architecture/module-design-and-integration.md)统一接口与边界，[分工表](process/module-ownership.md)指定主责组。D-02 转由 M2；资源仲裁仍由 M1；通知与部署由 M3。共享任务基础和前端外壳由 M2 牵头。此为 DEC-02 修订提案，须依据三组人日估算确认。

## 3. 三组并行迭代

| 迭代 | M1 交付 | M2 交付 | M3 交付 | 共同出口 |
| --- | --- | --- | --- | --- |
| 1：评审与任务拆分 | M1 边界、仲裁/HTTP 契约案例、估算 | M2 规则、身份/主数据和共享库设计、估算 | M3 状态机、通知/部署设计、估算 | 确认需求基线、职责、接口及维护人；记录未决项 |
| 2：公共骨架 | 冻结资源 HTTP 契约，提供可运行契约桩；开始真实仲裁 | 交付身份/RBAC、服务身份、基本主数据、前端外壳、最小共享任务基础 | 交付 CI/迁移执行入口、容器启动、通知基础和测试邮件渠道 | 三组同环境可启动；桩明确标识，不计为真实资源集成通过 |
| 3：并行业务闭环 | 搜索/预约/签到/历史，接入通知；提醒和违约 | 申请/两级审批/超时/撤销，接入资源客户端和审计 | 上报/派单/维修/升级/验收/评价，接入资源客户端和通知 | 各组业务测试通过；M1 真实资源端就绪，尚未通过的真实联调持续记录 |
| 4：真实集成与恢复 | 原子仲裁、来源追溯、资源端恢复 | 牵头 INT-01 截止与回执核对；提供主数据影响支持 | 牵头 INT-02/04，验证多工单和通知重试 | 真实 HTTP+MySQL、并发、重复、响应丢失及重启验收；移除验收中的桩 |
| 5：交付与展示 | M1 验收证据、指标定义 | 权限/审批验收证据、公共审计查询 | 牵头空环境部署、版本标识、审批和回滚实演 | 主功能全组版本、行为测试破坏验证、review 材料与未完成项 |
| 6：DSH 附加交付 | 提供并验收 M1 工具契约 | 提供身份、授权和会话适配 | 提供插件安装、配置、健康检查和发布配合 | DSH 插件通过公开 HTTP 接口真实调用 M1/M2/M3；豆包仅作为可替换模型适配器 |

迭代是依赖与出口，不是每组必须等待上一模块完成。公共桩支持调用方并行开发，但实际行为、冲突和写回必须替换为真实实现验收。共享通知基础在 M1 提醒开发之前交付；公共接口未冻结不能让三组 AI 自行猜字段。

## 4. 质量与发布

按需求 ID 分派任务，人工评审方案与变更；公共层、接口和 schema 由使用组评审。SQL 迁移版本化、种子幂等；通知站内逻辑事件去重，外部投递按至少一次语义处理，不承诺不可能证明的绝不重复邮件。测试失败阻止部署，记录实际运行结果。

M3 指定发布协调人，负责服务器申请进度、部署窗口、全组版本和回滚安排；生产审批由指定人员执行，不等于发布协调人可以自行批准。期中申请服务器前使用本地容器验证，不将其描述为生产部署。review 节点见 [版本流程](process/reviews-and-versioning.md)。

## 5. 当前状态与下一步

当前已形成并提交规划文档，应用尚未实现。下一步三组估算任务和确认 DEC-02、业务未决项，再启动并行骨架；主功能完成后按第 6 迭代实现 DSH 插件。实现/测试证据记录在 [需求索引](requirements/baseline.json) 与 [进度](progress.md)，工程伦理包括数据最小化、越权防护、公平占用、误违约纠正与真实开发记录，贯穿每轮评审。
