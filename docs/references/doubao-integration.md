## 可以借鉴与需要调整

- 保留模型调用在后端统一封装，前端不持有模型密钥。配置通过安全环境设置，不写入代码、日志或聊天。
- 在 React 实现浮窗、加载、快捷提问、错误和清空状态；使用同源 /api 路径，不硬编码 127.0.0.1 端口。
- Go 封装模型适配器，配置模型 ID、合法目标地址、超时、输出上限；实际使用时按当前火山方舟官方文档核对接口与模型能力，不照抄旧 bot 前缀判断。
- 参考 chat 出错后返回固定文案，接口仍为成功；本项目应明确 degraded/error 和回复来源，不能把备用文案描述成真实模型结果或业务成功。
- 模型服务失败时不原样暴露上游错误体；用户仅见安全错误和 correlationId，内部诊断日志脱敏。
- 本项目所有 AI 接口明确认证、范围、限流和输入长度；不能因为前端发送 token 就假设后端强制认证。
- 多轮会话按登录用户隔离，服务端构建有限上下文；不直接信任客户端传入 system/assistant 角色或工具结果。本地保存聊天需考虑退出清理和共用电脑隐私。

## 从问答扩展到课程业务代理

问答接入与业务代理是两个阶段。课程附加项须经公开接口真实操作 M1/M2/M3，不能生成一段“已预约”的文字就算完成，也不能让代理直接查改其他模块数据库。

建议链路：React 会话 → Gin AI 编排 → 豆包意图/工具参数 → 服务端允许列表校验 → 当前用户授权的 M1/M2/M3 公开 API → 结构化真实结果 → 用户回复。

| 工具能力提案 | 对应模块 | 约束 |
| --- | --- | --- |
| 查询座位、创建预约、本人历史 | M1 | 时间、院系和冲突规则仍由业务 API 执行 |
| 提交整室申请、查询、撤销本人申请 | M2 | 申请权限与当前状态仍由 M2 执行，不自动授予审批权 |
| 故障上报、查询、早期取消本人单 | M3 | 按 M3 合法状态和范围执行 |

模型只提出结构化操作，不授予权限。代理使用用户上下文和限定服务身份，不能凭内部服务权限替学生执行管理员动作。缺日期、时段、地点或目标记录时先追问；变更前展示目标与影响并确认，确认后将同一操作 ID 持久化、执行及核对。重复会话请求不得重复创建预约或工单，超时未知不得声称失败或成功。

模型输入、上传说明和业务文本不作为系统指令；仅允许预定义工具与字段，禁止执行任意 SQL、脚本或用户提供的调用地址。只向模型发送最少必要且获授权的信息，不发送凭证、完整签到码或其他学生资料。

任务书建议 DSH 插件作为接入方式。此模型适配可作为后续插件的能力之一；仅实现 Web 聊天窗口不等于已完成 DSH 插件安装、配置和调用流程。

## 责任和迭代提案

该附加项不新增第四组，也不替代主功能。建议项目组选一名集成负责人；M1/M2/M3 各提供自己的公开工具契约和验收，D 身份/审计负责人配合授权与追踪。负责人尚未确定，不将其默认交给某组。

主功能与集成先完成 → 模型问答适配 → 只读工具真实查询 → 带确认的写操作 → DSH 插件与部署验证。是否接入豆包、账号、模型和费用尚未确认；此阶段不要求用户提供密钥。

## 验收

1. 未认证、跨用户会话或超权限工具调用被拒绝，且不发出越权业务写入。
2. 参数缺失先追问；拒绝确认不写入；确认后能观察真实 API 与数据库状态变化。
3. 冲突、业务拒绝和模型不可用分别反馈，不能由模型伪造成功。
4. 重复操作、模型超时与业务响应丢失使用同一幂等标识核对；服务重启可恢复。
5. 多轮上下文不跨用户，前端历史不冒充服务端上下文；退出时清理适当的本地状态。
6. 模型请求超时、限流、非 JSON、空 choices 和无密钥等异常可控且不泄露密钥。
7. 工具允许列表和提示注入防护测试、真实网络业务集成、插件部署均有真实证据；当前全部未执行。
