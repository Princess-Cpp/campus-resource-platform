# M3 物业报修工单需求

主责：第三组（M3 组）；公共层及联调责任见 [分工表](../process/module-ownership.md)。

状态：待评审。课程要求上报、派单、维修中、超时升级、验收评价及维修下架/验收恢复；具体时限和取消政策是提案。

## 角色与权限

| 角色 | 允许行为 | 数据范围 |
| --- | --- | --- |
| 报修人 | 上报、查询本人、早期取消、完工后评价 | 本人工单 |
| 调度员 | 查看、派单、重派、处理升级 | 获授权区域 |
| 维修人员 | 接单、开始维修、提交完工 | 当前分配给本人的工单 |
| 验收人 | 验收通过或拒绝 | 获授权区域，不能验收本人维修 |
| 物业主管 | 处理升级、授权异常处理 | 获授权区域 |
| 运营管理员 | 统计 | 授权范围的脱敏聚合 |

默认验收人为场地管理员，报修人负责评价；不要求报修人一直在场。一个用户可有多个角色，但角色组合不能绕过验收职责分离。系统管理员配置账户权限，不自动成为物业主管。

## 业务需求

### M3-01.1 故障上报

必填：空间 ID、故障类别（照明/电源/桌椅/门窗/其他）、描述（建议 10–1000 字）；可选座位 ID、最多 3 张图片、严重程度（一般/紧急）。紧急标记需由调度员复核，不自动改变权限或派单顺序。上报时从 D 校验空间存在、用户可访问；停用但仍有维修需求的空间可上报，注销资源不能新增工单。

系统生成编号并记录报修人、时间、空间名称快照；同一幂等键重试只产生一张工单。对相似报修提示已有工单，但不自动合并，以免吞掉真实故障。图片建议 JPEG/PNG，每张 <=5MB，校验实际格式、去除位置等元数据，随机文件名，经授权接口读取，不提供执行能力。

验收：未登录、空间无权限、描述过短、座位不属于教室、伪装图片或超限上传均拒绝；重试不重复建单；两份真实不同上报仍可分别保存；图片不能通过猜路径读取。

### M3-01.2 派单、接单与重派

调度员选择具有维修角色且处于启用状态的人员，填写处理建议；维修人员确认接单，接单记录不等于开始维修。无人可派时保持 REPORTED 并提示主管。ASSIGNED 状态可重派，IN_PROGRESS 可由调度员交接重派但保持维修阻塞，旧维修人立即失去变更权；重派不能重置计时逃避超时升级。

验收：超区域派单、派给停用用户失败；重复派单使用版本控制避免覆盖；旧维修人重派后不能提交完工；维修中重派不会恢复座位；未接单不能开始维修。

### M3-01.3 开始维修与全室下架

维修人员开始前调用资源公共接口，以 M3+工单 ID 创建持续维修阻塞。仅阻塞确认后转 IN_PROGRESS，响应丢失时显示“维修准备中”并查询/幂等重试。课程基线按全室下架，即使故障字段指向单个座位也不只挡一个座位；单座位维修为扩展。

建议：维修一经开始，所有未结束个人预约标记“维修取消”，通知、释放其占用且免记违约，已签到也按提前终止记录实际使用；未来重叠整室预约交给 M2 中断/取消并通知，不静默放行。建立阻塞先于补偿处理，避免补偿期间新预约。上述已有预约处理需组内确定，见决策表。

验收：阻塞创建失败不进入 IN_PROGRESS；创建响应丢失不重复阻塞；下架后任何新个人预约和整室批准均被拒绝；已有预约处理不会触发迟到违约；多个工单来源分别保存；补偿漏跑重启后可继续且不重复取消。

### M3-01.4 完工与验收

维修人员提交处理结果、完工时间和可选结果图片，进入 AWAITING_ACCEPTANCE，阻塞保持。授权验收人检查结果，拒绝须填理由并返回 IN_PROGRESS，保留历次完工/验收记录；通过先触发本工单阻塞释放并核对，确认后 COMPLETED。维修人员不能验收本人执行或曾参与维修的工单；无合格验收人时不能自动通过。

“已验收、恢复处理中”作为同步状态展示；释放失败不虚报教室恢复。即使释放成功，是否可预约仍取决于其他工单、M2 占用、开放时间和停用标记。

验收：缺处理结果不能完工；未完工不能验收；自验收失败；拒绝后仍不可预约；两个维修工单只完成一个不恢复；释放响应丢失重复处理不影响其他阻塞；重复验收不产生第二次完成记录。

### M3-01.5 取消与异常关闭

建议：REPORTED/ASSIGNED 可由报修人取消，未开始不产生资源释放；取消须可选说明，已取消不能重新派单。维修准备中的结果未知时不直接取消，先核对是否已阻塞。IN_PROGRESS/AWAITING_ACCEPTANCE 普通用户不得取消；确属误报由主管发起异常关闭，需说明并由不同的验收人确认场地可用，随后释放本来源并进入 CLOSED。

验收：取消与开始并发不留下已取消工单阻塞；维修中取消被拒绝；主管不能单人强制清除安全阻塞；异常关闭保留完整理由、确认和审计；不能直接改成 COMPLETED 掩盖误报。

### M3-01.6 评价

建议：仅报修人对 COMPLETED 工单在完成后 7 天内评价一次，评分整数 1–5，文字可选且 <=500 字；提交后不修改，CLOSED/CANCELLED 不参加维修满意度。评价不改变工单和资源状态。冒犯性内容处理须留处置审计，不允许物业人员静默改分。

验收：评价他人工单、未完成工单、过期、非整数或超范围评分失败；到期边界与重试符合统一规则；重复请求仅一条评价；统计排除无评价记录，不把未评价当作零分。

### M3-01.7 查询与运营统计

本人列表、区域调度列表、维修待办、验收待办支持状态、日期、类别筛选和稳定分页。详情展示时间线、参与人、升级、资源同步状态；报修人联系方式仅派单相关人员按需可见。运营统计包含派单耗时、首修响应、总维修耗时、验收耗时、超时率和评分数量。

耗时定义：派单=首次派单-提交；首修=首次开始维修-提交；维修=所有实际维修段累计（重派不清零，待验收不计维修段）；验收=各待验收段累计；关闭/取消单独统计。

验收：跨用户与跨区域记录访问被拒绝；重派不会缩短首修或擦除耗时；无评价不进入均分分母；记录更名仍可追溯；列表图片和联系方式按权限裁剪。

### M3-02.1 超时检测与升级

提案：提交后 4 小时未派单，派单后 4 小时未首次开始，实际维修累计 24 小时未完工，待验收 24 小时未处理，分别通知区域主管。当前阶段重新进入的同类超时事件以阶段实例 ID 区分；每实例每升级等级一次。若主管未配置则产生管理员可见异常，不丢弃事件。

到期即 >= 阈值；持续按自然时间计时，未来若采用工作日需单独评审。升级是独立标记，不替代状态、不解除阻塞。参数版本随阶段记录，重派不刷新期限；服务重启补扫未处理超时。

验收：阈值前不升级、阈值时升级；任务重跑只有一次业务升级事件；通知失败不丢升级；验收拒绝回维修后形成新阶段并继续累计维修耗时；完成工单不再触发新的升级。

### M3-02.2 通知与审计

上报、派单/重派、开始维修、完工、验收通过/拒绝、取消、升级、异常关闭和评价处置使用 D 的通知与审计服务。维修导致的 M1/M2 预约变化由相应业务模块发通知，M3 不代写其数据库或重复发同一业务通知。

验收：收件人按当前参与人和权限选择；旧维修人只收到交接通知，不持续收到新处理详情；通知失败可重试而不再次触发业务流转；每次派单、重派、验收和异常关闭都有可追溯操作者。

## 状态表

| 当前状态 | 动作 | 新状态与条件 |
| --- | --- | --- |
| REPORTED | 派单 | ASSIGNED |
| ASSIGNED | 接单 | ASSIGNED，记录 acceptedAt |
| ASSIGNED | 开始维修 | IN_PROGRESS，接单及资源阻塞确认 |
| IN_PROGRESS | 完工 | AWAITING_ACCEPTANCE，提交处理结果 |
| AWAITING_ACCEPTANCE | 验收拒绝 | IN_PROGRESS，保留阻塞 |
| AWAITING_ACCEPTANCE | 验收通过 | COMPLETED，仅释放本工单来源且确认 |
| REPORTED/ASSIGNED | 合法取消 | CANCELLED，无开始维修操作残留 |
| IN_PROGRESS/AWAITING_ACCEPTANCE | 主管异常关闭+独立安全确认 | CLOSED，释放确认 |

终态不可复用；再次故障建新单并关联原单。业务状态与阻塞同步状态分离，准备/释放未确认期间禁止相反动作。超时升级不改变此表。

页面：上报、本人列表/详情、调度台、维修工作台、验收工作台、主管超时列表与统计。M3 拥有工单、分派、阶段、处理验收、评价及同步记录；用户与空间来自 D，预约来自 M1/M2。
