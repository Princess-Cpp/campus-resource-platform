# 基线与加固范围

范围分级用于约六人的三组团队，先交付课程必需行为与最低正确性，再追加可验证的加固。每条编号需求保留，不因暂缓而从索引消失。baseline.json 的 delivery_tier 为 baseline/mixed；mixed 表示基线与加固在同一需求内共存，其 baseline_scope/hardening_scope 分别说明，不将整条模糊地推迟。

## 首版基线

- M1：全部课程功能，院系访问、整点预约、默认最多4小时、每日教室码、提前15分钟及迟到10分钟推送、15分钟未签到取消/释放/违约、历史复用、运营统计和插座筛选。
- M2：权限门槛、多级审批、拒绝/撤销、超时、审批占用与来源释放。
- M3：上报、派单、维修、超时升级、验收、评价；全室维修阻塞、多工单来源恢复。
- D：身份/RBAC与范围、主数据/开放规则、通知、操作审计、统一资源仲裁及来源追溯。
- 最低正确性：数据库原子冲突检查、基本幂等、来源版本/等效迟到保护、持久化操作与重启补扫；截止结果核对、权限限制和必要补偿。这些不能以“加固”为由删掉。
- 工程：版本化迁移、幂等种子、构建和真实测试、测试自动部署、生产审批/回滚、部署协调和真实网络写回证据。

## 限制首版规模

| 子域 | 基线交付 | 后续加固，不计首版完成条件 |
| --- | --- | --- |
| D-01 账户与权限 | 统一登录/会话期限、禁用/撤权、角色和范围、用户/服务身份 | 完整账号恢复产品、复杂动态权限编辑体验、高级滥用检测 |
| D-02 主数据/参数 | CRUD与注销、基本开放表、院系范围、合法参数；各模块保存影响现存业务的必要快照 | 任意节假日规则编辑器、丰富参数版本浏览和自动迁移策略 |
| D-03 通知与审计 | 同事务本地事件、站内去重、真实外部渠道、有限重试、审计查询 | 通用多渠道偏好中心、高级导出、独立远程汇聚 |
| D-04 仲裁与恢复 | 并发不双占、来源保护、基本版本/栅栏、核对结果与重启扫描 | 通用可视化对账异常队列、跨服务高可用基础设施 |
| D-05 公共工程 | 最小共享库、统一连接池、迁移、健康、CI/部署、备份恢复演练 | 独立多服务数据库身份、通用调度平台和完整可观测平台 |
| M3 附件 | 如交付图片则限制大小/真实类型与授权读取；可先交付纯文本上报 | 图片元数据清洗和丰富上传管理；未清洗前不允许上传含隐私样例 |
| M3 异常关闭 | 基线采用正常取消与独立验收，不提供主管强制解除安全阻塞入口 | 特殊异常关闭双人确认、处置流程 |
| M1/M2/M3 统计 | 基本指标与明确分母，不伪称精确测量 | 高级分组、报表导出和分析仪表盘 |
| 业务代理 | 任务书第五部分的附加交付；不计入主功能基线 | DSH 插件运行时、豆包适配器、M1/M2/M3 工具、真实接口调用和部署验证 |

不提供加固入口时，界面不展示假按钮，需求索引明确 postponed，不宣称完成。开放时间例外、紧急停用等提案可后续补充；基线仍要拒绝非法开放修改或停用有未处理预约的资源，不留下数据不一致。

范围/参数变化需三组评审，课程明确要求不能降级。每轮 review 更新真实实现与未完成项；本文件未表示任何功能已经实现。
