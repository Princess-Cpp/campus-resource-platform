# 第一次小组讨论：项目推进议程

状态：讨论材料；其中“待讨论问题”不是已经批准的需求或技术决策。

本材料对应课程第一次讨论，适用于 6 人小组、3×45 分钟。讨论重点是推动项目形成可执行决定，而不是只展示已经写出的页面。

## 1. 讨论目标与结束时应有的产出

本次讨论需要完成：

1. 确认首版需求基线、加固项和任务书第五部分的 DSH 附加项边界；
2. 确认 M1、M2、M3 和 D 子域的责任、依赖和并行顺序；
3. 走读当前架构与 M1 代码，区分已实现、开发适配、待实现和待验收；
4. 确认项目级规则文件和 AI 任务交付格式；
5. 形成风险登记、待决问题、负责人和下一迭代任务。

结束时应留下：需求基线修订记录、依赖图、D 子域维护人表、资源 HTTP 契约待办、风险表、下一迭代任务卡和真实验证证据清单。

## 3. 三个 45 分钟环节

### 第一节：需求基线与任务依赖（45 分钟）

| 时间 | 内容 | 结果 |
| --- | --- | --- |
| 0–5 分钟 | 说明目标和讨论产出 | 确认本次不是单纯进度汇报 |
| 5–15 分钟 | 介绍仓库当前状态 | 区分 M1 已有代码和全项目完成度 |
| 15–28 分钟 | 需求基线和验收范围 | 标出基线、加固、附加项 |
| 28–40 分钟 | 任务分解和依赖 | 形成 M1/M2/M3/D 依赖图 |
| 40–45 分钟 | 现场确认问题 | 选出优先推进的 2–3 个问题 |

### 第二节：架构、代码与第一次迭代（45 分钟）

| 时间 | 内容 | 结果 |
| --- | --- | --- |
| 0–5 分钟 | 回顾第一节决定 | 防止重复讨论 |
| 5–15 分钟 | React、Go/Gin、MySQL 和单应用架构 | 明确模块边界和 HTTP 边界 |
| 15–30 分钟 | M1 查询、预约、历史、取消/签到演示 | 页面、API、数据库行为可追踪 |
| 30–39 分钟 | 第一次迭代验收标准 | 每项功能有行为验收 |
| 39–45 分钟 | 讨论代码缺口 | 确认 fixture、M2/M3 和集成缺口 |

### 第三节：AI 协作、风险和推进（45 分钟）

| 时间 | 内容 | 结果 |
| --- | --- | --- |
| 0–10 分钟 | `AGENTS.md` 与 AI 工作流 | 统一“先方案、再实现、再验证” |
| 10–25 分钟 | 风险登记 | 每项风险有证据、影响、动作和负责人 |
| 25–36 分钟 | 现场推进关键问题 | 对接口、分工或范围形成决定/暂定方案 |
| 36–42 分钟 | 下一迭代任务分派 | 任务卡包含目录、依赖和验收命令 |
| 42–45 分钟 | 总结和确认证据 | 记录未决项，不把提案写成已决定 |

## 5. 需求和依赖讨论内容

首版基线包括：M1 座位预约、M2 整室申请审批、M3 物业报修、D 身份/主数据/通知/审计/资源仲裁，以及权限、并发、幂等、迁移和恢复等最低正确性要求。

建议在白板上画出以下依赖：

```text
D-01 身份/RBAC ─┐
D-02 空间主数据 ├──> M1 座位预约
D-03 通知/审计 ─┤
D-05 任务基础 ─┘

M1 资源 HTTP 接口 ──> M2 审批占用整室资源
M1 资源 HTTP 接口 ──> M3 维修阻塞整室资源
M1/M2/M3 公开接口 ─> DSH 业务代理（附加项）
```

分工提案需要在课堂确认具体成员，而不能只保留组名：M1 维护资源仲裁和资源契约；M2 维护身份、主数据、审计和共享任务基础；M3 维护通知、部署规范和发布协调。最终结论应记录参与者、日期、依据和受影响需求。

## 6. 现场推进问题

下列问题是待讨论项，不是已经批准的需求：

1. M2 审批和 M1 个人预约同时发生时，谁优先？
2. M3 维修开始后，已签到学生如何处理，是否免除违约？
3. D-01、D-02、D-03、D-04、D-05 的具体维护人、评审人和联调人是谁？
4. M1 资源 HTTP 接口何时冻结，是否用 OpenAPI 或契约测试固定？
5. 幂等键、来源版本、截止时间和未知响应如何定义？
6. 哪些内容是第一迭代基线，哪些必须明确标记为加固或后续附加项？
7. M2/M3 什么时候替换开发 fixture，正式认证和服务身份如何接入？

优先推进第 3、4、6 项，因为它们决定三组能否并行。

## 7. 风险登记格式

| 风险 | 当前证据 | 影响 | 本周动作 | 负责人 |
| --- | --- | --- | --- | --- |
| M2/M3 后端缺口 | 当前主要为 M1 实现 | 项目偏成单模块 | 各组交付最小业务闭环 | 待确认 |
| 资源契约未冻结 | 路由和设计已有，正式版本不足 | 调用方各自猜字段 | 输出资源接口 v1 和失败示例 | M1 + M2/M3 |
| fixture 认证 | `dev-fixture.json` | 不能证明正式权限 | 给出 D-01 替换方案 | M2 |
| 集成证据不足 | 并发/重启/响应丢失未完整验收 | 演示成功不等于可靠 | 安排真实集成测试 | 三组 |
| 文档和代码不同步 | README/progress 旧描述 | 评审误判进度 | 指定文档维护人并更新状态 | 待确认 |
| 范围膨胀 | DSH、加固项和主功能同时推进 | M1 关键路径过载 | 先锁定基线 | 项目负责人 |
