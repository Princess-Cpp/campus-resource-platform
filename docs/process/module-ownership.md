# 模块组分工与公共层归属提案

用户已明确团队分为三个模块组，分别负责 M1/M2/M3。本文用“第一组（M1 组）”“第二组（M2 组）”“第三组（M3 组）”作为代称，不表示真实组号或成员姓名已经确定。三个业务模块归属来自用户说明；D 及工程公共工作的分配是具体提案，尚待组内评审。

## 总分工

| 交付范围 | 主责模块组 | 必须交付 |
| --- | --- | --- |
| M1 自习座位预约 | 第一组（M1 组） | 搜索、预约、签到、提醒/违约、历史、运营；处理 M2/M3 写回后的可用性与预约影响 |
| M2 整教室申请与审批 | 第二组（M2 组） | 需求细化、申请、逐级审批、撤销、超时、历史统计；调用资源接口占用/释放 |
| M3 物业报修 | 第三组（M3 组） | 需求细化、上报、派单、维修、升级、验收、评价；调用资源接口下架/恢复 |
| D 空间、座位、开放规则、业务参数管理 | 第一组（M1 组），建议 | D-02.1–D-02.3，统一配置接口和管理页面 |
| D 资源冲突仲裁、来源追溯、资源侧对账 | 第一组（M1 组），建议 | D-04.1–D-04.3，M1/M2/M3 共用资源 HTTP 契约与并发验证 |
| D 身份、登录、RBAC、权限管理 | 第二组（M2 组），建议 | D-01.1–D-01.3，三模块使用统一身份和权限定义 |
| D 审计事件规范、汇聚与查询 | 第二组（M2 组），建议 | D-03.3，审计查询与访问控制；各组自行记录本模块事件 |
| D 通知投递、站内消息与偏好 | 第三组（M3 组），建议 | D-03.1–D-03.2，统一通知接口、真实渠道和失败重试 |
| D 契约目录与兼容性检查 | 第二组牵头，三组供给及评审，建议 | D-05.1；契约作者仍是对应接口提供组，不能把所有接口实现交给第二组 |
| D 迁移约定、种子及基础流水线 | 第三组牵头，三组维护自身部分，建议 | D-05.2；统一执行入口和 CI，各组承担自己的 SQL 和测试数据 |
| D 健康、后台任务规范与数据治理 | 第三组牵头，三组实现及评审，建议 | D-05.3；检查约定与部署脚本，各组提供健康接口、任务幂等与数据保留策略 |

D 不建立第四个模块组。每项公共功能指定一个负责组，该组负责实现和维护，其他组通过接口使用并负责各自接入。具体协作步骤见 [模块协作与集成开发](module-collaboration.md)。

## 主责与使用方的界限

- 主责组负责公共能力的需求、接口、实现、管理界面、测试、迁移、说明和故障修复；公共变更须其他使用组评审。
- 各业务组负责调用公共能力，落实本模块的状态限制、数据范围、审计事件和通知事件；不能把这些业务代码都交给公共能力负责人。
- M2/M3 各自维护源业务同步记录、重试与补偿；M1 负责资源侧幂等、冲突和来源检查，不能只让一端负责一致性。
- D-02.3 的参数管理由 M1 提供；每个业务组定义自己参数的含义、约束和冻结策略，不由 M1 决定所有业务政策。
- 通知系统由 M3 维护，但 M1 的提醒触发与 M2 的审批事件仍由各自业务组实现。
- 审计汇聚由 M2 维护；三组各自保证本地业务状态与审计事件可靠落库，不能依赖远程审计成功才宣称跨库原子性。
- 基础流水线由 M3 牵头；每组仍维护自己的构建测试入口。生产批准、上线窗口和版本选择由项目组共同安排，不自动授予某组发布权。

## 跨组联调责任

| 链路 | 牵头 | 配合 | 验收责任 |
| --- | --- | --- | --- |
| INT-01 M2 → M1 整室占用/释放 | M2 组 | M1 组 | 双方确认真实 HTTP、冲突与超时恢复 |
| INT-02 M3 → M1 维修下架/恢复 | M3 组 | M1 组 | 双方确认多工单与来源释放 |
| INT-03 来源追溯 | M1 组 | M2/M3 组 | 三组确认业务与审计可关联、访问权限正确 |
| INT-04 维修/停用对既有预约影响 | 触发方 M3 或资源方 M1 | M1/M2 组 | 三组确认通知、取消/终止、免违约及补偿 |

故障先由失败接口提供组牵头；调用方提供 operationId/correlationId 与请求版本。不清楚故障位置时双方联查，不默认归责某一组。

## 为什么这样分与如何评审

资源归 M1 是为了统一预约和跨模块占用仲裁；权限、审计归 M2 与审批治理相邻；通知归 M3 与工单通知和升级相邻。这说明职责关联，并不证明工作量均衡。M1 需求更详细可节省需求分析，但资源并发和集成仍较重；M2/M3 细化需求的时间也必须计入工作。

评审前每组分别估算需求澄清、前端、后端、测试、集成与公共工作，记录人日区间和可投入人力。若 M1 过载，可优先调整 D-02 参数/主数据管理的实现责任，而资源仲裁保留单一所有者；若 M3 过载，可改由 M2 牵头流水线，但不要拆成多套不兼容部署。调整后同步本表和 baseline.json，不能只口头变更。
