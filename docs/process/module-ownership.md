# 模块组分工与公共层归属（DEC-02 修订提案）

依据 [Issue #1](https://github.com/sunanfeng/campus-resource-platform/issues/1) 修订。业务模块仍归对应模块组；D 的主责、公共工具和发布角色按下表安排。具体成员、人日估算和三组评审记录待填写。

## 主责表

| 范围 | 唯一主责组 | 配合与交付边界 |
| --- | --- | --- |
| M1 全部业务 | M1 | 预约、签到、提醒、违约、历史、统计 |
| M2 全部业务 | M2 | 申请、逐级审批、撤销、超时 |
| M3 全部业务 | M3 | 上报、派单、维修、升级、验收、评价 |
| D-01 身份/RBAC及资源 HTTP 服务身份 | M2 | 三组使用统一认证；M1 接入服务身份校验 |
| D-02 空间、座位、开放规则、通用参数存储 | M2 | M1/M3 评审资源变更影响；每组自行定义本模块参数及校验 |
| D-03.3 审计公共库 | M2 | 各组在业务事务内写统一审计事件，无远程汇聚服务 |
| D-04 资源仲裁、来源保护与必要恢复 | M1 | M2/M3 维护调用侧操作、补偿与对账 |
| 资源 HTTP 契约（D-05.1） | M1 | M2/M3 评审；M3 将兼容性检查接入 CI |
| 最小共享任务/outbox/幂等存储/可控时钟库 | M2 | 第一迭代指定一名维护人；M1 提供提醒与仲裁使用案例，M3 提供重试案例；业务幂等仍由各组负责 |
| 前端外壳 | M2 | 路由、登录、布局、统一 API 客户端与错误处理；各组只维护各自业务页面 |
| D-03.1/03.2 通知公共库与投递任务 | M3 | M1/M2 在事务内产生通知事件；公共任务库供三组复用 |
| D-05.2/05.3 迁移入口、流水线、部署、健康约定 | M3 | 各组写自己的迁移、种子、健康接口和测试 |
| 发布协调与服务器申请 | M3 | 指定一名发布负责人，可轮值；安排部署窗口、版本、申请材料、回滚和审批记录；生产批准人另行指定 |

共享任务库由 M2 承担是本轮负担调整提案，不将公共基础全部追加给 M1。骨架迭代只做三组共用的最小接口和持久化能力，不开发通用调度平台、消息中间件或任意工作流。

## 集成决策和联调

| 链路 | 牵头组 | 决策与验收 |
| --- | --- | --- |
| INT-01 截止确认、整室占用/释放 | M2 | M2 收敛审批成功界点方案，M1 必须评审资源一致性；无法一致时提交项目评审，不由任一组单方面改契约 |
| INT-02 维修下架/恢复 | M3 | M1 评审阻塞与来源恢复，双方联调 |
| INT-03 来源追溯 | M1 | M2/M3 提供源记录与审计 |
| INT-04 维修/停用对已有使用的影响 | M3 | M1/M2 处理本模块取消/终止；M2 配合主数据停用事件 |

主责组负责方案、接口、实现、测试和故障处理；使用组负责自身接入、业务校验和恢复。业务数据按 Go 包/仓储边界维护，不能跨模块改表；单应用共享受控连接池不等于模块可以随意访问彼此仓储。

## 工作量评估与调整机制

组内预计每组约两人。先逐项估算人日区间，再确认 DEC-02；不能根据“M1 需求已详细”或“M2 最轻”直接判定负担。下表是评审必填项，不将空白估算当成已完成决策。

| 组 | 需求澄清 | 业务前后端 | 公共能力 | 测试/集成 | 可投入人日 | 总人日区间/维护人 |
| --- | --- | --- | --- | --- | --- | --- |
| M1 | 待估 | 待估 | D-04、资源契约 | 并发、来源、恢复 | 待填 | 待填 |
| M2 | 待估 | 待估 | 身份、主数据、审计、最小任务库、外壳 | 权限、主数据、审批 | 待填 | 待填 |
| M3 | 待估 | 待估 | 通知、流水线、部署 | 状态机、重试、发布 | 待填 | 待填 |

拆分到可审查任务，记录低/高估算与依赖；在每轮 review 比较实际投入。若 M2 公共任务超载，优先缩减扩展、安排跨组共同实施或转移完整子域，不拆出多套身份、任务库或资源仲裁。具体任务移交同步本表、索引与迭代计划。

## 决策记录

原方案：M1 同时承担主数据与资源仲裁；存在关键路径和过载风险。候选：一组独占 D、按原子域分摊、按本表重新分摊。本表减轻 M1 主数据工作，集中单应用基础库并明确空缺职责；M2 的新负担须先估算，不能宣称已实现均衡。

状态：修订提案；参与者、日期、实际估算、异议、最终采用范围和负责人姓名待真实评审后记录。评审处理详见 [Issue #1 调整记录](review-1-response.md)。

## 后端代码位置

维护组与包名分开：M1 维护 `backend/internal/booking`（含当前资源仲裁）；M2 维护 `backend/internal/classroom` 与 `backend/internal/identity`；M3 维护 `backend/internal/maintenance/domain`。开发适配器位于 `backend/internal/dev`，组合入口位于 `backend/cmd/server`。目录调整不变更需求 ID、组别或来源标识；公共职责的评审状态保持原样。见 [目录调整与验证](../implementation/backend-package-layout.md)。
