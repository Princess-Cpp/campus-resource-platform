## 2. 系统结构与模块边界

React 页面 → Go/Gin HTTP API → 对应模块业务逻辑 → 模块仓储 → MySQL。前端和后端位于同一仓库；生产由 Go 提供前端构建产物，发布一个应用，MySQL 独立运行。开发时 Vite 可以独立运行并代理 /api。

| 模块 | 业务主责 | 公共能力维护提案 | 禁止越界 |
| --- | --- | --- | --- |
| M1 组 | 座位搜索、预约、签到、提醒、违约、历史与统计 | D 统一资源仲裁、来源追溯、资源 HTTP 契约 | 不代替 M2 作审批决定，不代替 M3 验收 |
| M2 组 | 整教室申请、多级审批、撤销与到期 | D 身份/RBAC与服务身份、空间主数据、审计、前端外壳与最小任务公共库 | 不直接修改资源占用或工单表 |
| M3 组 | 报修、派单、维修、升级、验收与评价 | D 通知、迁移入口、流水线、部署与发布协调 | 不直接取消 M1/M2 业务记录或修改资源表 |

各组自己维护本模块前后端、测试、SQL 迁移、业务审计和通知事件。公共能力由负责组实现和维护，调用组负责自己的接入。D 是按子域分配的公共能力，不成立第四组。牵头公共工作不意味着替其他组编写所有迁移和测试。

建议目录：frontend/src/modules/{m1,m2,m3,common}；backend/internal/{m1,m2,m3,common}；backend/cmd/server；backend/migrations；contracts；tests；infra；scripts。实际脚手架尚未创建。公共子域在 common 下分别设 identity/resources/notifications/audit，禁止形成任意模块相互调用的杂物包。

## 3. 所有模块一致使用的数据与命名

| 项目 | 约定提案 |
| --- | --- |
| 稳定 ID | API 用字符串；数据库可使用整数或 UUID，不让前端依赖数字精度 |
| JSON 命名 | lowerCamelCase，例如 roomId、sourceBusinessId |
| 时间 | ISO 8601 且带时区，服务端统一时间点存储，界面 Asia/Shanghai；避免使用 MySQL 默认会话时区隐式解释 |
| 区间 | [startAt,endAt)，相邻区间可用；整点规则按业务时区验证 |
| 状态 | 使用明确英文枚举；业务状态与同步状态分离 |
| 分页 | page 从 1 开始，pageSize 默认 20、最大 100；稳定排序且以 ID 打破时间并列 |
| 状态版本 | version 为递增整数，敏感修改带 expectedVersion，过时返回版本冲突 |
| 来源 | sourceModule 为 M1/M2/M3，sourceBusinessId 为原业务 ID；操作状态和原因不能只存一个 seat.status |
| 关联追踪 | X-Correlation-Id 对应 correlationId；接收端验证或生成安全标识并传递 |

登录身份来自 D 验证的凭证，不从请求 body 的 userId/role 推断权限。用户动作同时检查角色、院系/区域/本人范围和业务状态。模块调用资源使用服务身份，资源端限制允许的来源和动作，不允许通过 body 自称管理员或伪造其他组来源。用户登录凭证与内部服务凭证类型不同，均不硬编码或出现在文档示例中；服务身份签发/配置与校验由 M2 负责、M1 接入，具体协议需在身份契约中确认。

统一成功返回示例：{"data":{"id":"operation-id"},"correlationId":"trace-id"}。失败示例：{"error":{"code":"RESOURCE_CONFLICT","message":"目标时段已占用"},"correlationId":"trace-id"}。详情不能泄露其他学生身份、令牌或签到码。

| HTTP / 错误码 | 语义 | 调用方处理 |
| --- | --- | --- |
| 400 INVALID_INPUT | 字段、时区或区间不合法 | 修正请求，不自动重试 |
| 401 UNAUTHENTICATED | 身份无效 | 重新认证，不能继续写入 |
| 403 FORBIDDEN | 动作或范围不允许 | 不自动重试 |
| 404 NOT_FOUND | 无可访问记录 | 不泄露记录是否存在于其他范围 |
| 409 RESOURCE_CONFLICT | 明确占用冲突，无新占用确认 | 提示冲突，不循环重试审批 |
| 409 VERSION_CONFLICT / IDEMPOTENCY_CONFLICT | 版本过时或同键不同内容 | 核对状态，不换新键盲目提交 |
| 202 OPERATION_PENDING | 已接收，尚未确认生效 | 查同一操作，不显示最终成功 |
| 503 DEPENDENCY_UNAVAILABLE | 依赖暂不可用 | 同键核对/退避重试；不能仅凭该响应推断无副作用 |

成功写入可返回 201，结果查询返回 200；普通响应丢失、超时和连接错误均是结果未知，不等于明确业务冲突。

## 4. 资源公开接口：M1 提供，M2/M3 调用

路径和字段为共同评审提案，不声称服务已经运行。所有写操作在 /api/v1/internal/resources 下，不能被学生直接调用。可用性用户接口另按权限过滤。

| 接口 | 作用 | 调用者 |
| --- | --- | --- |
| GET /api/v1/resources/availability | 查询有权访问资源的区间可用性及脱敏原因 | 前端/M1/M2 |
| POST /api/v1/internal/resources/operations | 创建占用、维修阻塞或释放操作 | M2/M3；M1 内部统一仲裁 |
| GET /api/v1/internal/resources/operations/{operationId} | 核对确认、冲突、待处理和已释放的结果 | 来源所属模块 |
| GET /api/v1/internal/resources/sources | 按授权来源核对有效占用，供对账 | 来源所属模块 |

写入携带 Idempotency-Key。共同字段：operationId、action、sourceModule、sourceBusinessId、sourceVersion、roomId、reason、correlationId。action 为 HOLD_ROOM_INTERVAL、BLOCK_ROOM_MAINTENANCE 或 RELEASE_SOURCE。

- HOLD_ROOM_INTERVAL：M2，须 startAt/endAt/deadlineAt；整室占用只允许在截止前确认，并统一仲裁个人占用、整室占用、维修和停用。
- BLOCK_ROOM_MAINTENANCE：M3，持续阻塞直到明确解除；不设预计完成时自动释放，允许多工单来源并存。
- RELEASE_SOURCE：只能释放自身业务来源；带更高的 sourceVersion，维护终态栅栏，防止迟到的旧创建重新生效；来源尚不存在也记录相应版本而非删除保护。

确认响应至少含 operationId、operationStatus、sourceModule、sourceBusinessId、sourceVersion、effectiveAt 和结果摘要；写入生效、明确冲突、已释放的操作结果持久化。相同键相同请求返回同一操作；相同键不同内容拒绝。operationId 由业务模块生成并持久化，后续重复请求与查询沿用。

资源操作状态：PENDING → CONFIRMED 或 FAILED。网络结果未知在调用方标记 UNKNOWN，不能写成资源已经 FAILED。RELEASE_SOURCE 的 CONFIRMED 表示该来源已无有效占用，不代表整个教室都可用。失败错误码单独保存。

个人预约、整室占用和维修阻塞通过同一资源仲裁逻辑落库。MySQL 小时槽唯一约束为整点预约提案，需配合房间级一致锁顺序和事务，防止整室/增座/维修竞争；不能仅靠“查可用再插入”。资源侧不能部分成功整室写入。取消自身占用不删除其他来源。

## 5. 业务状态和两条主要写回链路

M1：RESERVED → CHECKED_IN → FINISHED；合法取消或维修/停用终止留原因。M2：SUBMITTED → DEPARTMENT_APPROVED → APPROVED；拒绝、取消、超时、紧急终止为相应终态。M3：REPORTED → ASSIGNED → IN_PROGRESS → AWAITING_ACCEPTANCE → COMPLETED；拒绝验收回 IN_PROGRESS，早期取消和异常关闭按其需求执行。本文列核心流程，合法动作、角色和边界以各模块需求完整状态表为准。

### INT-01：最终审批与占用

1. M2 核对操作者、流程、业务版本和截止，持久化待确认操作，不提前显示 APPROVED。
2. M2 通过 HTTP 创建 M2 区间来源；资源端在统一事务中核对截止和冲突，持久化决定回执。
3. 截止前确认的回执作为批准成功界点，M2 核对后保存 APPROVED、审计和通知事件；回执丢失可查回。
4. 明确冲突不占位，申请保留待最终审批并提示；待审批不锁座，既有个人预约不被普通审批驱逐（DEC-04 提案）。
5. 撤销、到期与确认竞争先核对回执和版本，不能盲目 EXPIRED；释放自己的来源并对账，不复活已撤销占用。

审批期限、门槛、时长等仍按 DEC-03/05 待评审。资源端与 M2 必须共同验证截止成功界点，不能假设两次 HTTP/SQL 操作是一个事务。

### INT-02：维修阻塞与恢复

1. M3 合法开始维修，持久化创建阻塞操作；资源端确认后才记录 IN_PROGRESS。
2. 阻塞先禁止全室新预约，再通过可靠影响通知由 M1/M2 处理已有使用（DEC-06 提案）。
3. 完工待验收仍保持阻塞；验收拒绝继续维修。
4. 合法验收通过后释放本工单来源，核对确认后 COMPLETED；恢复处理中不宣称座位已可预约。
5. 其他维修、M2 区间占用、停用和开放规则仍参与判定。恢复不自动复活已取消预约。

### INT-03/04：追溯和既有使用

每次写入记录来源、业务 ID、操作和 correlationId。M3/资源端产生 ROOM_MAINTENANCE_STARTED、ROOM_MAINTENANCE_ENDED 或 ROOM_DISABLED 影响事件，事件字段至少 eventId、roomId、sourceModule、sourceBusinessId、occurredAt、sourceVersion。建议事件按版本持久化，通过授权 HTTP 消费入口和接收回执投递，具体事件端点与顺序协议需双方另行评审并写入 OpenAPI。

M1/M2 各自幂等处理自己记录，取消/终止并通知，不让 M3 写预约表。维修取消免违约；事件重复、乱序和延迟不能取消维修后重新建立的合法预约，接收方须结合资源当前版本与影响时间范围核对，不能按 roomId 无条件取消所有记录。

## 6. D 接入约定

- 身份权限：三组使用统一用户/角色/权限定义；模块自行检查当前业务角色和状态，禁止自审批、自验收。撤权需及时生效。
- 主数据与参数：资源 ID 稳定；参数按模块命名和版本保存，改变未来参数不追溯改变旧业务政策。
- 通知：业务组发 eventId、业务 ID、接收者和模板数据；通知组持久化、去重和重试。取消后抑制无效提醒，不通过重复业务操作重发通知。
- 审计：每组将关键变更与本地审计事件事务持久化，使用进程内审计库，不建立远程汇聚服务。原/新状态、原因、来源和 correlationId 可查询，不记录凭证和完整签到码。
- 迁移：各组维护自己表和迁移，公共 schema 共同评审；空库可重放、种子幂等，禁止手工改库。

通知、审计、任务和身份的进程内 Go 公共接口在各公共子域实现前统一定义；不能假定 Gin 内置这些完整业务能力。使用共享连接池，但数据共享只读也须经过授权模块接口，不以同一数据库为理由跨模块直接访问内部仓储。

## 7. 故障恢复和联调验收

调用方保存操作/状态，提供方保存回执与来源版本；超时先查询再同键重试，使用有限退避和异常队列。服务重启扫描未完成操作；每项业务与资源结果定期对账。单应用 HTTP 调用前结束本地事务，不跨网络持锁；补偿仅操作自己来源。模块内测试与实际 HTTP/MySQL 集成都需要，不用 mock 替代整个资源逻辑。

| 必测案例 | 预期结果 |
| --- | --- |
| M2 最终通过 | 区间内所有座位不可预约，区间外不受影响 |
| 个人预约与整室批准并发 | 不双占；失败一方无部分占用 |
| 到期、撤销、迟到写入竞争 | 合法回执和终态一致，无残留或复活来源 |
| 维修开始 | 全室下架；绕过搜索直接提交也失败 |
| 两工单只验收一张 | 另一来源仍阻塞，M2/停用也未被清除 |
| 资源成功但响应丢失、进程重启 | 结果查询恢复，逻辑写入不重复 |
| 相同键不同内容、来源伪造 | 请求拒绝，无越权状态变化 |
| 影响事件重复/乱序与迟到扫描竞争 | 不误取消新预约、不错误新增违约 |
| 通知投递暂不可用或本地审计写入失败 | 投递事件保留可重试；关键审计写入失败则业务事务回滚 |

各次验证记录 Git commit、输入、业务/操作 ID、HTTP 证据、资源实际变化和断言，不输出凭证。至少一次暂时破坏冲突检查/来源过滤，确认测试失败，恢复后重跑。当前上述测试全部未执行。

## 10. DeepSeek Harness（DSH）业务代理架构

任务书第五部分要求在主功能完成基础上实现自然语言业务代理，并建议以课程个人 Lab 分析的 DeepSeek Harness（Everything is a Plugin.，简称 DSH）插件形式接入。它是本项目的附加交付，不新增第四模块组，但必须从架构上预留清晰边界。

部署链路为：React 会话界面 → Gin 代理适配层 → DSH 插件运行时 → 受限工具适配器 → M1/M2/M3 已公开 HTTP 接口。DSH 插件只负责会话、意图理解和工具编排；业务规则、权限、事务和状态写回仍由对应模块负责。插件不得直接访问任一模块数据库或内部包。

各模块提供版本化工具契约：M1 提供查询座位、创建预约、查询本人历史；M2 提供提交整室申请、查询申请、撤销本人申请；M3 提供故障上报、查询工单、取消本人工单。工具调用必须经过当前用户授权、允许列表、参数校验、幂等键和确认流程。缺少时间、地点或目标时先追问；写操作在执行前展示目标并要求确认；模型超时或业务结果未知时不得声称成功。

插件安装、配置、密钥注入、健康检查、版本标记和回滚纳入部署流水线。豆包只是可替换的模型适配器，不能代替 DSH 插件运行时；[豆包集成参考](../references/doubao-integration.md)记录适配细节。该附加项不改变 M1/M2/M3 主功能验收，也不允许用聊天演示代替真实接口集成。

## 11. Issue #1 修订与交付范围

[修订分工](../process/module-ownership.md)指定各公共子域唯一主责，INT-01由M2收敛方案并经M1评审，INT-04由M3牵头。身份/主数据/通知/任务骨架与资源契约先并行交付，再三组并行业务闭环。

审计和通知采用本地库，同业务事务写审计/outbox，不建远程汇聚；共享任务基础由M2维护，业务回调归各组。[范围分级](../requirements/scope.md)和索引为每条需求划分基线与加固；本总约定的内部接口仍需评审，必要并发/来源/重试/恢复不能删除，但通用异常控制台等不作为首版条件。
